# M2详细设计：专题入口与推荐阅读结构

这份设计文档说明 `M2` 为什么选择专题入口与推荐阅读增强，以及本轮会如何接入当前站点底座。

## 设计目标

把当前站点从“按目录浏览的知识库”升级到“兼具模块入口和专题入口的知识站点”，也就是：

- 首页可以直接进入高价值专题
- 专题页可以承接推荐阅读链路
- 专题生成逻辑保持脚本化
- 后续继续扩展更多专题时不需要手工堆很多页面

## 为什么在 M2 选专题入口与推荐阅读增强

`M1` 已经把首页和模块总览页做得更像正式入口，但当前站点仍然主要依赖“顶层模块目录”来组织内容。对于大量资料型仓库来说，这一层还不够，因为用户真正想找的往往不是“目录名”，而是某个主题集合。

所以 `M2` 的重点不是继续补目录层，而是补一层“主题组织层”。

## 本轮复杂度中心

本轮真正的复杂度中心主要有四个：

- 哪些专题应该先做成正式入口
- 推荐阅读如何既有质量，又不脱离自动生成逻辑
- 首页、专题导航页和模块页之间如何建立清晰层次
- 专题配置如何做到可持续扩展

## 设计方案

### 设计一：先做少量高价值专题

本轮不追求一次做很多专题，而是优先把下面几个高价值专题接起来：

- Vue / Nuxt
- 面试整理
- 构建与工程化
- AI 学习

### 设计二：专题页由“专题说明 + 模块覆盖 + 推荐阅读”三部分组成

每个专题页至少包含：

- 当前专题覆盖的模块范围
- 专题定位说明
- 推荐阅读列表
- 对应模块入口列表

### 设计三：推荐阅读继续以自动规则为主

本轮继续坚持：

- 先用模块优先入口与高价值入口组合出推荐阅读
- 先不做复杂人工标注系统
- 先让专题页可稳定生成，再考虑后续精调

### 设计四：新增 `专题导航/` 作为总入口页

这一层用于承接所有专题入口，避免首页直接承担所有主题聚合压力。

## 本轮交付物

本轮预期交付物包括：

- 首页专题推荐增强版
- `专题导航/index.md`
- 多个专题详情页
- `04-M2任务拆解-专题入口与推荐阅读增强.md`
- `05-M2详细设计-专题入口与推荐阅读结构.md`
- `06-开发记录-VitePress专题入口与推荐阅读增强.md`

## 风险与约束

本轮主要约束有这些：

- 专题入口仍要以自动生成优先
- 原始 Markdown 资料不进行专题标签手工回填
- 推荐阅读规则要尽量简单、稳定、可解释
- 构建成功仍然是硬约束

## 完成后的预期效果

完成后，当前站点应该达到下面这些状态：

- 首页已经具备专题推荐能力
- 站点已经有独立专题导航层
- 用户不只可以按模块进入，也可以按主题进入
- 后续补搜索、SEO 和发布时，站点信息架构会更完整
