# M6 任务拆解：治理优先级与质量基线增强

这份任务拆解文档用于承接 M6：在 M5 已经完成站点治理总览与基础校验链路后，继续把治理推进到“可排序、可比较、可阻止回归”的阶段。

## 本轮目标

让站点治理从“知道有问题”，进化到“知道先治哪里、是否回归”。

## 本轮交付范围

- 治理热点模块排序
- 质量基线文件
- docs:check 基线回归比较
- CI 质量报告归档

## 任务拆解

### 任务一：热点模块优先级排序

目标：把零散问题汇总成模块级热点，让治理工作能排优先级。

子任务：

- 为每个模块计算缺少一级标题、资源缺失、空文件、重复标题等指标
- 生成模块治理得分
- 在站点治理页展示热点模块
- 为热点模块生成建议治理路径

### 任务二：质量基线建立

目标：为当前巡检结果建立一份可比较的基线。

子任务：

- 增加基线文件
- 固定关键指标的当前值
- 让后续巡检可以和基线比较

### 任务三：本地回归校验

目标：让 `docs:check` 不只是输出摘要，还能判断关键问题是否回升。

子任务：

- 读取基线文件
- 对比占位页、缺少一级标题、缺失资源、重复标题
- 如有回归则在本地命令中失败

### 任务四：CI 结果归档

目标：让远端校验结果可被保留与查看。

子任务：

- 在 GitHub Actions 中上传质量报告产物
- 输出 step summary，方便直接查看关键指标
- 保持现有 Pages workflow 不受影响
