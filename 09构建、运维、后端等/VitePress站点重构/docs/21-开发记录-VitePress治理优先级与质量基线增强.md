# 开发记录：VitePress 治理优先级与质量基线增强

## 背景

M5 已经让站点拥有了治理页和基础校验命令，但那一轮更偏“看见问题”。

M6 的目标是进一步回答两个更实际的问题：

- 这么多问题，先修哪一块
- 以后再改站点时，问题有没有变多

## 本轮改动

### 1. 增加模块级治理热点排序

这一轮把原先分散的问题聚合到了模块维度，计算每个顶层模块的治理得分，并在 `站点治理` 页面里展示热点模块和建议治理路径。

### 2. 增加质量基线文件

新增 `scripts/docs-quality-baseline.json`，把当前核心指标固定成一份基线。这样后续巡检结果就有了比较参照。

### 3. docs:check 增加回归比较

现在 `docs:check` 除了检查构建产物和治理报告外，还会和基线比较：

- 占位/空文件
- 缺少一级标题
- 缺失资源
- 重复标题

只要这些指标变大，就会直接失败。

### 4. CI 增加质量报告归档

`docs-check.yml` 现在会把 `quality-report.json` 作为 artifact 上传，方便后续查看与对比。

## 本轮价值

这轮完成后，站点治理开始具备真正的“闭环”特征：

- 能看见问题
- 能排序优先级
- 能阻止回归
