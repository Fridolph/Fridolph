# 技术博客：VitePress 知识站如何用一次试点把治理真正做起来

## 治理的关键，不是发现问题，而是敢做第一次修复

很多知识库项目都会在某个阶段拥有巡检脚本、治理页、质量指标，甚至还有 CI。

但如果始终没有一次真实修复，这套治理体系就很容易停留在“看板”层面。

M7 这一轮的重点，其实就是做这第一次。

## 为什么试点比全面开修更重要

面对几百个缺少一级标题的文档，最容易犯的错误就是想“一口气全修完”。

但更稳的做法往往是：

- 先挑一个体量可控的模块
- 先验证修复规则
- 先验证构建和展示没有副作用
- 再决定是否扩大范围

这也是为什么这一轮先选 `07四艺` 做治理试点。

## 自动修复脚本的价值，不只是省时间

自动修复脚本真正重要的地方，不只是能省掉很多重复劳动，而是它会逼着你把规则讲清楚：

- 什么算缺少一级标题
- `index.md` 应该用什么做标题
- frontmatter 文件怎么插入标题
- 已经合规的文档要不要跳过

当这些规则被脚本化之后，治理就开始从“人工经验”变成“可复用能力”。

## 趋势展示为什么很重要

只看绝对数量时，人很难感知治理是不是有效。

但一旦加上“较基线下降多少”的趋势表达，治理就开始有了反馈。

这会极大提高维护者继续清理下一批问题的动力，因为效果是看得见的。

## 结语

如果说 M5、M6 主要是在搭建治理系统，那么 M7 更像是在给这套系统做一次真正的通电测试。

从这一步开始，知识站治理终于不只是：

- 有问题清单
- 有热点排序
- 有回归守门

而是开始具备了最关键的一点：真的动手修，而且修完之后还能看见变化。
