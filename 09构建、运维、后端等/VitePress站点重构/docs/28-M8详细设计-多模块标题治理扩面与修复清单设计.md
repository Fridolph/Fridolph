# M8 详细设计：多模块标题治理扩面与修复清单设计

这份详细设计文档用于描述 M8 的核心设计：如何把 M7 已验证的标题治理方法安全扩展到更多模块，并让治理页开始形成“已完成 / 下一步”的任务清单视图。

## 设计目标

M8 主要解决两个问题：

- 如何把试点修复能力扩到更多模块
- 如何让治理页更像可执行的治理面板

## 一、扩面模块选择

本轮继续优先选择：

- `04非典型工具、类库等`
- `10其他`

选择原因：

- 当前缺少一级标题数量较高
- 文件结构相对稳定
- 多数文档适合沿用文件名 / 目录名推导标题

## 二、脚本复用策略

M8 不新增新的修复逻辑，而是复用 M7 的 `fix-missing-h1`：

- 普通文件使用文件名作标题
- `index.md` / `README.md` 使用目录名作标题
- frontmatter 文件仍然把一级标题放在 frontmatter 后方

## 三、治理页增强设计

### 3.1 本轮已治理模块

通过固定配置列出已完成标题治理扩面的模块，并结合最新质量报告展示它们当前的标题缺失数量。

### 3.2 下一批推荐模块

从当前治理热点中排除已治理模块，再取前若干个模块作为“下一批推荐模块”。

这样治理页会从单纯展示现状，进一步变成：

- 这一轮做了什么
- 下一轮该做什么

## 四、基线更新设计

完成扩面修复并通过自测后，更新基线文件，使更优结果变成后续守门标准。
