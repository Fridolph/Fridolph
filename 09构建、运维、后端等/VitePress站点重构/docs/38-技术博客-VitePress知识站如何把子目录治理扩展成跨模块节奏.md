# 技术博客：VitePress 知识站如何把子目录治理扩展成跨模块节奏

## 试点成立后，下一步不是放大模块，而是复制节奏

当一个治理试点跑通之后，最自然的冲动往往是继续去啃更大的整模块。

但对历史知识库来说，更稳的路径通常不是立刻做“大”，而是先做“可复制”。

## 为什么跨模块复用比继续单点扩面更重要

如果一种治理方式只能在一个模块里工作，那它还只是偶然成功。

只有当它能够在不同模块、不同目录结构里重复使用，才说明这套方法开始具备长期维护价值。

这也是 M10 选择把 `interviewMap的阅读笔记` 和 `Node入门2` 放在同一轮推进的原因。

## 为什么治理页要增加子目录级推荐

模块级热点能告诉我们“哪里问题大”，但还不够回答“下一步先动哪里风险最低、收益最高”。

子目录级推荐的价值，在于把一个过大的治理目标继续拆细，让下一步动作变得具体、可执行。

## 从 M7 到 M10，治理开始形成真正的节奏

当累计治理清单、本轮治理范围和下一批推荐子目录同时出现在治理页时，站点治理就不再只是一次次手工修补。

它开始表现出一种更稳定的节奏：

- 先选边界清晰的范围
- 再验证脚本和展示链路
- 再跨模块复制
- 最后把下一步继续拆小
