# M12 任务拆解：资源巡检降噪与资源治理试点

这份任务拆解文档用于承接 M12：在 M11 已把标题治理做成阶段化面板后，继续把治理范围从标题扩展到资源问题，并先解决资源巡检误报过多的问题。

## 本轮目标

让治理从“只会看标题问题”走向“开始处理资源问题”，同时回答两个问题：

- 当前资源缺失列表里，哪些是真的缺失，哪些是巡检误报
- 当资源治理开始落地后，治理页应该如何表达本轮范围和下一批建议

## 本轮交付范围

- 资源巡检规则降噪
- `07四艺/1琴/音乐RE0学习` 资源修复试点
- `10其他/wuxia/team/飞雪` 资源修复试点
- 治理页“下一批推荐资源问题页”增强
- 新基线回写

## 业务流程梳理

本轮按下面顺序推进：

1. 先用巡检脚本识别全站资源问题。
2. 再区分误报与真实缺失，先修正巡检规则。
3. 巡检结果稳定后，选择两个边界清晰的目录做资源修复试点。
4. 修复完成后，把本轮治理范围和下一批资源问题页回写到治理页。
5. 最后执行构建与巡检自测，确认结果可回写为新基线。

## 任务拆解

### 任务一：修正资源巡检误报

目标：让资源巡检不再把代码块、源码分析片段和普通函数调用误识别为 Markdown 资源引用。

### 任务二：推进乐理笔记资源治理试点

目标：修复 `07四艺/1琴/音乐RE0学习` 中历史图片命名错误，验证图片型资料可否稳定纳入治理节奏。

### 任务三：推进角色资料页资源治理试点

目标：修复 `10其他/wuxia/team/飞雪` 中首图缺失引用，验证单页面图片资源缺失问题的修复链路。

### 任务四：增强治理页资源视图

目标：让治理页开始提供“下一批推荐资源问题页”，使资源治理具备和标题治理类似的后续入口。

### 任务五：基线更新

目标：在巡检降噪和资源修复结果稳定后，把新的质量结果回写为新基线，避免旧误报继续干扰下一轮治理。
