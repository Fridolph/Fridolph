# M13 任务拆解：资源治理收口与示例表达校正

这份任务拆解文档用于承接 M13：在 M12 已完成资源巡检降噪与试点修复后，继续收口剩余资源问题，并把示例型内容改写成更明确的代码示例表达。

## 本轮目标

让资源治理从“已经起步”走向“本轮收口”，同时回答两个问题：

- 剩余资源问题中，哪些是历史缺图，哪些其实只是示例代码写法不够明确
- 当资源问题收口后，治理页应如何继续为下一轮质量治理让路

## 本轮交付范围

- `02CSS相关/响应式布局/响应设计` 示例表达校正
- `11Vue学习/vue2相关文档学习笔记/组件/6杂项/01编写可复用组件` 示例表达校正
- `03JavaScript/underscore源码/1笔记-核心方法` 历史缺图收尾
- 新基线回写

## 业务流程梳理

本轮按下面顺序推进：

1. 先确认剩余资源问题的真实类型。
2. 对示例型页面，把会被渲染的 HTML 片段改为代码块展示。
3. 对历史缺图页面，用可落地的文字说明替代失效图片引用。
4. 修复完成后重新生成治理页，确认资源问题归零。
5. 最后执行构建与巡检自测，并回写新基线。

## 任务拆解

### 任务一：校正响应式设计文档中的示例表达

目标：把原本直接渲染的 HTML 图片示例改为代码片段，避免示例代码被误识别为实际资源依赖。

### 任务二：校正 Vue 组件文档中的占位图片示例

目标：把 `src="..."` 这类占位写法从可渲染 HTML 改为代码示例，避免继续产生无意义的资源问题。

### 任务三：完成 underscore 源码笔记的历史缺图收尾

目标：移除无法恢复的历史图片依赖，并用文字说明保留原有讲解语义。

### 任务四：基线更新

目标：在资源问题归零后，把新的质量结果回写为基线，让下一轮里程碑重新聚焦标题、占位页和命名治理。
