# 开发记录：VitePress 资源治理收口与示例表达校正

## 背景

M12 让资源巡检从“噪声很多”变成“可以用”，但仍然留下了两类尾项：

- 示例代码被当成真实页面资源
- 历史博客迁移后遗留的缺图引用

M13 的目标不是继续扩面，而是先把这批剩余资源问题收口，让资源治理形成一个完整闭环。

## 开发顺序

本轮按下面顺序推进：

1. 先确认剩余资源问题的页面和成因。
2. 再把示例型 HTML 片段改成代码块。
3. 然后处理无法恢复的历史缺图引用。
4. 接着生成新治理页并检查资源问题是否归零。
5. 最后执行构建与巡检自测，并回写新基线。

## 本轮改动

### 1. 校正响应式设计文档中的 HTML 示例

把直接渲染的图片示例改为代码块，避免 `image.jpg` 被站点当成真实依赖。

### 2. 校正 Vue 可复用组件文档中的占位图片示例

把 `src="..."` 的演示片段改为代码块，让占位内容不再参与资源巡检。

### 3. 收尾 underscore 源码笔记的历史缺图

删除两张已无法恢复的活动对象示意图引用，并用文字说明保留原有讲解意图。

### 4. 回写质量基线

在资源问题清零后，把新的巡检结果写入基线，为下一轮里程碑恢复更稳定的比较起点。

## 自测记录

本轮自测执行：

- `npm run docs:sync`
- `npm run build`
- `npm run docs:check`

通过标准：

- 构建通过
- 巡检通过
- 资源缺失数量归零
