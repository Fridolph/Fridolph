# M14 任务拆解：标题治理扩面与热点子目录再推进

这份任务拆解文档用于承接 M14：在 M13 已把资源问题收口后，把治理重点重新切回标题缺失，并继续以热点子目录为单位推进新一轮扩面。

## 本轮目标

让治理从“资源问题收口”回到“标题问题继续下降”，同时回答两个问题：

- 当前标题缺失最适合继续治理的热点子目录是哪几块
- 标题治理是否还能在跨模块场景下继续稳定复用

## 本轮交付范围

- `00面试相关整理/02HTTP` 标题治理
- `09构建、运维、后端等/learn-webpack` 标题治理
- 新增脚本入口
- 新基线回写

## 业务流程梳理

本轮按下面顺序推进：

1. 先根据治理页的推荐子目录和缺少一级标题清单，确认本轮治理对象。
2. 再使用已有 `fix-missing-h1` 脚本执行批量修复。
3. 修复后重新生成治理页，确认本轮范围中的标题缺失归零。
4. 最后执行构建与巡检自测，并回写新基线。

## 任务拆解

### 任务一：推进面试 HTTP 子目录标题治理

目标：修复 `00面试相关整理/02HTTP` 中的缺少一级标题问题，继续降低面试模块的热点问题规模。

### 任务二：推进 learn-webpack 子目录标题治理

目标：修复 `09构建、运维、后端等/learn-webpack` 中的缺少一级标题问题，验证标题治理可继续跨模块复制。

### 任务三：补充脚本入口与治理配置

目标：为本轮治理范围补充脚本入口和治理配置，让治理页可以准确表达当前轮次。

### 任务四：基线更新

目标：在本轮修复结果稳定后，把新的标题缺失结果回写为基线，保证下一轮可以继续比较。
