# 技术博客：VitePress 知识站如何在资源收口后重新切回标题治理主线

## 当一类问题收口后，治理节奏就该回到主矛盾

资源问题收口之后，知识站的治理重点自然回到了标题缺失。

因为对一个以阅读为核心的站点来说，一级标题不仅影响页面语义，也会影响搜索结果、链接标题和读者的第一眼理解。

## 为什么还要继续按子目录推进

如果直接按模块整体推进，范围会太大，维护成本也会迅速上升。

按子目录推进的好处，是每一轮都能保持足够清晰的边界：

- 修了哪里
- 剩多少问题
- 下一轮该继续看哪里

这也是为什么在资源治理收口之后，标题治理仍然沿用同一套子目录级节奏。

## M14 为什么选择 HTTP 和 learn-webpack

这两个目录都处于当前热点列表前列，而且内容结构相对清楚。

一个代表面试知识整理，一个代表工程化学习资料。把它们放在同一轮治理里，可以继续验证：

- 脚本是否足够通用
- 治理节奏是否真的能跨模块复制

## 这轮真正重要的，不只是补了多少标题

M14 真正重要的是确认了一件事：在资源问题收口后，治理链路不需要重新发明。

标题治理依然可以沿用：

- 子目录级选题
- 批量修复脚本
- 里程碑表达
- 基线回写

这说明前几轮建立起来的治理方式，已经开始具备稳定的可持续性。
