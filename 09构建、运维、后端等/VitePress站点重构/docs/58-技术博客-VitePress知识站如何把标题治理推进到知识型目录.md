# 技术博客：VitePress 知识站如何把标题治理推进到知识型目录

## 标题治理真正难的，不是补标题本身

补一个一级标题这件事本身并不复杂。

真正复杂的是，当目录越来越深、知识点越来越碎时，治理动作还能不能保持低成本、可回放、可持续。

## 为什么 M15 要选择知识型目录

前几轮的很多治理对象都带有比较明显的专题特征，比如面试、工程化、资源问题修复。

但知识站里还有另一类内容：知识卡片和课程型笔记。这类目录通常文件很多、粒度很细，而且一级标题对阅读体验和搜索语义影响更直接。

把这类目录纳入治理，才能说明这套方式不仅能处理热点专题，也能处理知识库的基础层。

## JS API 和 Java 学习为什么适合作为一轮

这两个目录虽然都属于知识型内容，但结构并不一样。

- `JS API` 更像方法卡片集合
- `Java学习` 更像课程章节展开

把它们放在同一轮里，可以继续验证批量修复脚本的适配边界，也能让治理页上的里程碑表达更有代表性。

## M15 真正验证了什么

这一轮真正验证的不是“又修了多少标题”，而是：

- 多层目录仍然可以低成本治理
- 知识型目录也能稳定纳入同一节奏
- 里程碑驱动的方式仍然适合继续往前滚动

当这些都成立时，后续治理就不再只是修补问题，而是在持续给知识站打基础。
