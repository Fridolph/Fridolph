# Dao 阶段里程碑规划

这份文档用于定义当前仓库按 Dao 原则推进开发时的阶段性里程碑地图。

从这一版开始，后续功能开发统一采用：

`阶段规划 -> 任务拆解 -> 业务流程 -> 详细设计 -> 开发 -> 自测 -> 记录 -> Dao Commit 子任务提交`

---

## 总目标

让当前仓库从“文档与功能持续累积”进一步进入“按里程碑稳定推进、按子任务闭环沉淀、按 Dao Commit 有语义记录”的工程状态。

---

## 阶段拆分

### M1：Dao 交付闭环落地

目标：把 Dao 的交付原则真正落进仓库，建立后续每个里程碑都可直接复用的工作流、文档模板与脚手架能力。

本轮重点：

- 建立阶段里程碑总规划
- 建立 M1 的任务拆解、详细设计、开发记录和里程碑开发笔记
- 建立可复用的里程碑文档模板
- 建立里程碑脚手架脚本
- 接入仓库脚本入口并完成自测

完成标志：

- 后续里程碑不再需要从零定义文档结构
- 可以通过脚手架快速生成里程碑文档骨架
- 当前仓库已有完整 Dao 交付闭环示范

### M2：业务里程碑模板化落地

目标：把 M1 的交付闭环，从“规范存在”推进到“业务开发可稳定复用”。

本轮重点：

- 选定一个真实业务/内容治理主题作为样板里程碑
- 用 M1 产出的流程和模板完整跑通一次
- 补足业务流程图、状态流转和自测项沉淀方式
- 校验 Dao Commit 子任务提交流程是否顺畅

完成标志：

- 至少一个真实主题按新流程完整跑完
- 里程碑文档、开发记录和开发笔记能互相引用

### M3：知识复利与经验沉淀增强

目标：让里程碑推进结果不只停留在“完成”，而开始形成可复用经验。

本轮重点：

- 整理可复用的设计决策模板
- 沉淀自测清单模板
- 建立常见 Dao Commit 场景示例集
- 让历史里程碑更容易被检索和复用

完成标志：

- 里程碑之间出现稳定复用关系
- 经验沉淀开始从“文档记录”升级为“开发辅助资产”

### M4：可视化演进与对外表达

目标：让里程碑体系既能服务内部推进，也能服务对外表达。

本轮重点：

- 建立里程碑索引页或总览页
- 整理里程碑完成状态、主题关系与演进脉络
- 输出对外可读的 Dao 工程实践总结

完成标志：

- 读者能够快速理解这套工程方式如何运转
- 仓库具备对外展示的工程演进表达

---

## 当前默认执行策略

若没有额外指定里程碑主题，则默认优先推进当前最小闭环：

`M1 Dao交付闭环落地`

原因是：

- 这是后续所有里程碑的基础设施
- 先把执行方法稳定下来，后续开发节奏会更顺
- 它本身就能作为第一篇完整的 Dao 里程碑示范
