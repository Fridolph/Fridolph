# M10任务拆解：Vue2项目资料子目录治理深化

这份文档用于定义 `M10` 的任务拆解。

## 本轮目标

围绕 `11Vue学习/vue2相关整理都放这，vue3后的直接放目录下` 完成一轮按 Dao 流程推进的子目录治理闭环，继续压降全站缺少一级标题问题，并验证 Vue 历史项目资料目录在“批量补齐 + 语义收口”模式下是否也能稳定治理。

## 本轮范围

本轮范围包括：

- 锁定 `11Vue学习/vue2相关整理都放这，vue3后的直接放目录下` 为当前治理对象
- 梳理当前目录的业务流程、标题风险和命名边界
- 补充脚本入口并执行批量 H1 修复
- 对 `note`、`README`、项目总结等弱语义标题做二次语义化收口
- 完成自测、质量基线更新、开发记录和 Dao Commit 提交

本轮不包含：

- 进入 `05Nodejs/Node入门2`
- 修改底层标题修复脚本逻辑
- 同时并行治理 `11Vue学习` 下的其他子目录

## 拆解顺序

### 任务一：目标与现状梳理

目标：确认为什么在 M9 之后切换到 Vue2 项目资料目录。

完成标准：

- 已确认该目录当前缺少一级标题数量与收益
- 已说明为何本轮继续避开 `05Nodejs`
- 已识别 `note`、`README`、项目总结等弱语义标题风险

### 任务二：业务流程梳理

目标：把本轮主流程、异常回修和文档回写链路提前梳理清楚。

完成标准：

- 已明确“巡检 -> 批量修复 -> 语义收口 -> 自测 -> 记录”的主流程
- 已明确标题重复或构建失败时的回修策略
- 已明确沉淀文档位置和更新顺序

### 任务三：详细设计

目标：明确 Vue 历史项目资料目录的命名规范和脚本入口。

完成标准：

- 已形成独立详细设计文档
- 已明确脚本入口和二次命名策略
- 已明确质量基线更新方式

### 任务四：开发实现

目标：完成当前 Vue2 项目资料子目录的标题治理，并确保指标继续下降。

完成标准：

- 目标目录缺少一级标题文档已补齐 H1
- 弱语义标题已统一改为 `Vue2项目资料：<主题>` 或等价上下文标题
- `docs:sync` 与 `docs:check` 最终通过

### 任务五：自测与记录

目标：把本轮过程、设计判断、结果和经验完整沉淀到里程碑文档中。

完成标准：

- 开发记录已更新
- 里程碑开发笔记已更新
- 当前轮次已完成 Dao Commit 提交

## 本轮完成标准

- `11Vue学习/vue2相关整理都放这，vue3后的直接放目录下` 完成一轮子目录治理
- 当前质量基线得到更新或确认
- 里程碑文档组已形成完整闭环
- 当前子任务已按 Dao Commit 方式提交
