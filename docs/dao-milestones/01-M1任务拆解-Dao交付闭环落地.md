# M1任务拆解：Dao 交付闭环落地

这份文档用于定义 `M1` 的任务拆解。本轮目标是把 Dao 的指导原则，从“说明文档”推进到“当前仓库内可执行、可复用、可回溯”的交付闭环。

## 本轮目标

建立一套后续每个里程碑都能直接复用的执行底座，包括：

- 阶段里程碑规划
- 里程碑标准文档组
- 业务流程与详细设计的默认组织方式
- 里程碑脚手架
- 子任务提交与自测闭环

## 本轮范围

本轮聚焦“流程底座”本身，不直接扩展具体业务功能。

本轮范围包括：

- 里程碑规划文档
- M1 文档组
- 里程碑模板
- 脚手架脚本
- npm 脚本入口
- 自测与开发记录

本轮不包含：

- 新的业务模块实现
- 新的站点功能页面
- 自动化生成完整 Dao Commit 内容的 CLI

## 拆解顺序

### 任务一：建立阶段里程碑总规划

目标：先定义阶段视角，明确当前仓库后续里程碑如何推进。

完成标准：

- 有独立阶段里程碑规划文档
- 明确 M1 到后续阶段的关系
- 当前默认优先里程碑已确定

### 任务二：梳理 M1 业务流程与运转方式

目标：在进入详细设计前，先把“一个里程碑如何运转”梳理清楚。

完成标准：

- 能说清主流程、分支流程和异常处理流程
- 能说明一个子任务从开始到提交的闭环

### 任务三：形成详细设计

目标：明确 M1 将新增哪些文档、模板、脚本与脚本入口。

完成标准：

- 有独立详细设计文档
- 明确目录结构、输入输出、模板字段与脚本行为
- 明确自测方案

### 任务四：开发里程碑模板与脚手架

目标：把 M1 的设计变成可执行资产。

完成标准：

- 新增模板目录
- 新增里程碑脚手架脚本
- 新增 npm 入口

### 任务五：自测、修复与记录

目标：验证脚手架和文档资产已能正常工作。

完成标准：

- 至少完成一次脚手架执行验证
- 站点同步与构建校验通过
- 开发记录同步更新

### 任务六：补齐里程碑开发笔记

目标：在 M1 完成后，形成一篇完整的里程碑开发笔记。

完成标准：

- 已新增里程碑开发笔记
- 已说明本轮结果、价值与下一轮建议

## 本轮完成标准

本轮完成时，应满足：

- 已建立阶段里程碑总规划
- 已补 `M1` 任务拆解、详细设计、开发记录和开发笔记
- 已建立可复用模板
- 已建立脚手架脚本并完成验证
- 已完成自测
- 已完成当前子任务的 Dao Commit 提交
