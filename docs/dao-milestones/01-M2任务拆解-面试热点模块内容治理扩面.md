# M2任务拆解：面试热点模块内容治理扩面

这份文档用于定义 `M2` 的任务拆解。本轮目标是在 `M1` 已完成 Dao 交付闭环落地后，选定当前知识站最显著的质量热点模块，完整跑通一次真实的业务型里程碑。

## 本轮目标

围绕当前质量报告中的第一热点模块 `00面试相关整理`，完成一轮“从规划到治理到校验再到沉淀”的真实里程碑实践，验证 M1 建立的 Dao 交付方式已经具备业务复用能力。

本轮希望回答四个问题：

- 热点模块是否能按统一规则被稳定拆解和治理
- 当前应优先治理哪些子目录，而不是笼统治理整个模块
- 标题缺失、占位内容和导航表达如何形成同一条治理主线
- Dao 里程碑文档、脚手架、自测和子任务提交是否能在真实主题上跑通

## 本轮范围

本轮范围包括：

- 基于质量报告重新评估 `00面试相关整理` 的治理优先级
- 选择一个优先子目录作为首个治理对象
- 梳理内容治理主流程、分支流程和异常流程
- 完成该轮治理所需的详细设计
- 按子任务推进治理开发、自测、记录和提交

本轮不包含：

- 对所有热点模块同时扩面
- 对非优先子目录做无边界批量修复
- 对现有站点治理视图做大范围结构重写

## 拆解顺序

### 任务一：重新确认热点模块与优先子目录

目标：先判断当前最值得治理的对象，而不是直接开修。

本任务要回答：

- 为什么 `00面试相关整理` 是当前第一优先级
- 这个模块内部哪个子目录最适合作为 M2 首个治理对象
- 当前缺失类型是标题问题、占位问题，还是导航问题为主

完成标准：

- 已明确 M2 的首个治理子目录为 `00面试相关整理/2019高频知识点整理`
- 已说明选择依据：当前缺少一级标题 20 篇，为模块内第一热点，且问题类型单一、最适合首轮闭环治理

### 任务二：梳理内容治理业务流程

目标：先把治理如何运转梳理清楚，再进入详细设计。

本任务要覆盖：

- 主流程：热点识别 -> 子目录筛选 -> 修复 -> 校验 -> 回写记录
- 分支流程：批量修复可自动完成时如何推进
- 异常流程：修复后质量回归或页面异常时如何回退并修复

完成标准：

- 已有可读的主流程和异常流程说明
- 已明确本轮每一步输入和输出

### 任务三：形成详细设计

目标：明确本轮改哪些文件、为什么这样改、如何验证。

设计重点包括：

- 当前治理对象的目录与统计口径
- 是否需要新增或复用修复脚本
- 是否需要更新治理页、导航页或基线
- 本轮自测如何执行

完成标准：

- 已有独立详细设计文档
- 已明确开发边界和验证边界

### 任务四：执行首个治理子任务

目标：对首个治理对象 `2019高频知识点整理` 完成一次真实治理闭环。

本任务完成后，应包括：

- 内容修复
- 修复脚本入口补齐
- 质量基线回写
- 相关脚本或配置调整
- 文档同步
- 自测通过
- 开发记录更新
- Dao Commit 子任务提交

### 任务五：继续推进后续子任务直到完成当前里程碑

目标：按照同样的节奏，把当前里程碑内剩余子任务逐个完成。

执行规则：

- 当前子任务未自测通过，不进入下一个子任务
- 每个子任务完成后立即更新开发记录
- 每个子任务单独按 Dao Commit 提交

### 任务六：里程碑收口与开发笔记

目标：在 M2 完成后，补齐里程碑开发笔记，形成完整复盘。

完成标准：

- 已补 M2 开发记录
- 已补 M2 里程碑开发笔记
- 已对下一轮建议做说明

## 本轮完成标准

本轮完成时，应满足：

- 已选定并治理 `00面试相关整理/2019高频知识点整理`
- 已将质量基线从 `placeholderCount=25 / missingTitleCount=317` 更新到新结果
- 已完整跑通 Dao 里程碑流程
- 已完成所有子任务的自测闭环
- 已更新开发记录与开发笔记
- 已完成本轮所有 Dao Commit 子任务提交
