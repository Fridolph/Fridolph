# M9任务拆解：部署知识子目录治理深化

这份文档用于定义 `M9` 的任务拆解。

## 本轮目标

围绕 `09构建、运维、后端等/部署相关知识` 完成一轮按 Dao 流程推进的子目录治理闭环，在不干扰用户本地 Node 工作区的前提下，承接当前新的质量热点，继续稳定压降缺少一级标题问题。

## 本轮范围

本轮范围包括：

- 锁定 `09构建、运维、后端等/部署相关知识` 为当前治理对象
- 梳理本轮治理业务流程与异常回修路径
- 形成详细设计并补充脚本入口
- 完成标题治理、自测、记录和 Dao Commit 提交

本轮不包含：

- 进入 `05Nodejs/Node入门2`
- 修改底层标题修复脚本逻辑
- 同时并行治理多个运维/部署子目录

## 拆解顺序

### 任务一：目标与现状梳理

目标：明确为什么在 M8 之后切换到 `部署相关知识`。

完成标准：

- 已确认当前热点模块切换后的治理优先级
- 已说明为何本轮避开 `05Nodejs`
- 已说明该目录的标题风险特征

### 任务二：业务流程梳理

目标：让本轮主流程、异常流程和回写流程保持清晰一致。

完成标准：

- 已明确主流程
- 已明确回修策略
- 已明确沉淀文档位置

### 任务三：详细设计

目标：明确部署/运维类多层目录如何统一命名，避免 `note`、`nginx`、`准备工作` 等弱语义标题回归。

完成标准：

- 已形成独立详细设计文档
- 已明确脚本入口和命名策略
- 已明确基线更新方式

### 任务四：开发实现

目标：完成当前部署知识子目录标题治理，并确保指标继续下降。

完成标准：

- 目标文档已补齐 H1
- 未引入重复标题回归
- `docs:sync` 与 `docs:check` 最终通过

### 任务五：自测与记录

目标：把本轮过程、设计判断、结果与经验沉淀到里程碑文档中。

完成标准：

- 开发记录已更新
- 里程碑开发笔记已更新
- 当前轮次已完成 Dao Commit 提交

## 本轮完成标准

- `09构建、运维、后端等/部署相关知识` 完成一轮子目录治理
- 当前质量基线得到更新或确认
- 里程碑文档组已形成完整闭环
- 当前子任务已按 Dao Commit 方式提交
