# M10详细设计：Vue2项目资料子目录治理深化

这份文档用于说明 `M10` 的详细设计。

## 设计目标

在 `M9` 完成部署知识目录治理后，继续选择高收益且安全的治理对象 `11Vue学习/vue2相关整理都放这，vue3后的直接放目录下`，在不触碰用户本地 Node 工作区的前提下进一步降低全站缺少一级标题规模，并验证 Vue 历史项目资料目录也能稳定复用当前 Dao 治理闭环。

## 为什么选择 `11Vue学习/vue2相关整理都放这，vue3后的直接放目录下`

- 当前质量报告显示该子目录仍有 `18` 篇文档缺少一级标题，是安全目录中的高收益目标
- 当前全站热点第一位仍是 `05Nodejs`，但用户本地正在编辑 `Node入门2`，本轮继续优先避开该区域
- 该目录同时包含 `demo`、`iview-test`、`nuxt-demo`、`program/sell`、`vue-todo` 等不同项目形态，适合验证“项目资料型目录”的统一命名策略
- 该目录天然容易出现 `note`、`README`、`学习笔记`、`项目总结` 等弱语义标题，需要通过二次收口保证检索语义稳定

## 业务流程

### 主流程

1. 读取当前质量报告，确认 `Vue2项目资料子目录` 为本轮治理对象
2. 补充 `package.json` 脚本入口
3. 执行批量标题修复
4. 对修复结果做二次检查，并统一改为带上下文的语义标题
5. 执行 `docs:sync`
6. 执行 `docs:check`
7. 回写开发记录、开发笔记和质量基线
8. 完成 Dao Commit 提交

### 分支流程

如果批量修复后未出现重复标题和指标回归，仍执行目录内语义化收口，避免 `note`、`README`、`项目总结` 等弱标题继续残留在站点导航与搜索结果中。

### 异常流程

如果出现以下任一情况：

- 标题重复数量增加
- 构建失败
- 校验指标回归

则必须在当前轮次内继续修复，直至 `docs:check` 重新通过。

## 模块边界

- 仅治理 `11Vue学习/vue2相关整理都放这，vue3后的直接放目录下`
- 不触碰 `05Nodejs/Node入门2` 及其相关本地改动
- 不修改 `scripts/fix-missing-h1.mjs` 本身
- 不把本轮扩展成 `11Vue学习` 全模块批量治理

## 自测设计

本轮自测顺序固定为：

1. `npm run docs:fix-h1:vue2-legacy`
2. `npm run docs:sync`
3. `npm run docs:check`

全部通过后，才算 `M10` 当前轮次完成。
