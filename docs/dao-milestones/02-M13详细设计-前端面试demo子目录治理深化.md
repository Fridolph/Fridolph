# M13详细设计：前端面试demo子目录治理深化

这份文档用于说明 `M13` 的详细设计。

## 设计目标

在 `M12` 完成 LearnTypeScript 目录治理后，继续选择高收益且安全的目标 `00面试相关整理/前端面试demo`，在不触碰用户本地 Node 工作区的前提下进一步降低全站缺少一级标题规模，并验证面试题归纳型目录也能稳定复用当前 Dao 治理闭环。

## 为什么选择 `00面试相关整理/前端面试demo`

- 当前质量报告显示该子目录仍有 `9` 篇文档缺少一级标题，是安全目录中的稳定收益目标
- 目录内同时包含 HTML/HTTP、CSS、JavaScript、React 四类内容，适合验证跨主题面试资料的统一标题收口策略
- 该目录没有额外空页面，适合聚焦“标题可读性”和“目录语义稳定性”的纯治理场景
- 当前全站热点第一位仍是 `05Nodejs`，但用户本地正在编辑 `Node入门2`，本轮继续优先避开该区域

## 业务流程

### 主流程

1. 读取当前质量报告，确认 `前端面试demo` 为本轮治理对象
2. 补充 `package.json` 脚本入口
3. 执行批量标题修复
4. 对修复结果做二次检查，并统一改为带上下文的语义标题
5. 执行 `docs:sync`
6. 执行 `docs:check`
7. 回写开发记录、开发笔记和质量基线
8. 完成 Dao Commit 提交

### 分支流程

如果批量修复后未出现重复标题和指标回归，仍执行目录内语义化收口，避免 `html`、`css`、`js`、`笔or一`、`01` 这类弱标题继续残留在站点导航与搜索结果中。

### 异常流程

如果出现以下任一情况：

- 标题重复数量增加
- 构建失败
- 校验指标回归

则必须在当前轮次内继续修复，直至 `docs:check` 重新通过。

## 模块边界

- 仅治理 `00面试相关整理/前端面试demo`
- 不触碰 `05Nodejs/Node入门2` 及其相关本地改动
- 不修改 `scripts/fix-missing-h1.mjs` 本身
- 不把本轮扩展成 `00面试相关整理` 全模块批量治理

## 自测设计

本轮自测顺序固定为：

1. `npm run docs:fix-h1:frontend-demo`
2. `npm run docs:sync`
3. `npm run docs:check`

全部通过后，才算 `M13` 当前轮次完成。
