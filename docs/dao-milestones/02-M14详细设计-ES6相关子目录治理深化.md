# M14详细设计：ES6相关子目录治理深化

这份文档用于说明 `M14` 的详细设计。

## 设计目标

在 `M13` 完成前端面试 demo 目录治理后，继续选择高收益且安全的目标 `03JavaScript/ES6+相关`，在不触碰用户本地 Node 工作区的前提下进一步降低全站缺少一级标题规模，并验证 ES6 学习资料目录也能稳定复用当前 Dao 治理闭环。

## 为什么选择 `03JavaScript/ES6+相关`

- 当前质量报告显示该子目录仍有 `7` 篇文档缺少一级标题，是安全目录中的稳定收益目标
- 目录内同时包含总览笔记、学习指南、Generator 专题与装饰器学习笔记，适合验证多种知识表达形态下的统一标题收口策略
- 当前重复标题中已有 `README`、`note`、`学习笔记`、`总结` 等弱标题命中本目录，本轮有机会顺带降低重复标题数量
- 当前全站热点第一位仍是 `05Nodejs`，但用户本地正在编辑 `Node入门2`，本轮继续优先避开该区域

## 业务流程

### 主流程

1. 读取当前质量报告，确认 `ES6+相关` 为本轮治理对象
2. 补充 `package.json` 脚本入口
3. 执行批量标题修复
4. 对修复结果做二次检查，并统一改为带上下文的语义标题
5. 执行 `docs:sync`
6. 执行 `docs:check`
7. 回写开发记录、开发笔记和质量基线
8. 完成 Dao Commit 提交

### 分支流程

如果批量修复后未出现重复标题和指标回归，仍执行目录内语义化收口，避免 `README`、`note`、`总结`、`学习笔记` 等弱标题继续残留在站点导航与搜索结果中。

### 异常流程

如果出现以下任一情况：

- 标题重复数量增加
- 构建失败
- 校验指标回归

则必须在当前轮次内继续修复，直至 `docs:check` 重新通过。

## 模块边界

- 仅治理 `03JavaScript/ES6+相关`
- 不触碰 `05Nodejs/Node入门2` 及其相关本地改动
- 不修改 `scripts/fix-missing-h1.mjs` 本身
- 不把本轮扩展成 `03JavaScript` 全模块批量治理

## 自测设计

本轮自测顺序固定为：

1. `npm run docs:fix-h1:es6`
2. `npm run docs:sync`
3. `npm run docs:check`

全部通过后，才算 `M14` 当前轮次完成。
