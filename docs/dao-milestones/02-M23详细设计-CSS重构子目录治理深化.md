# M23详细设计：CSS重构子目录治理深化

这份文档用于说明 `M23` 的详细设计。

## 设计目标

在 `M22` 完成 `02CSS相关/CSS学习` 治理后，继续选择高收益且安全的目标 `02CSS相关/CSS重构`，在不触碰用户本地 `05Nodejs` 工作区的前提下进一步降低全站缺少一级标题规模，并验证章节型目录也能稳定复用当前 Dao 治理闭环。

## 业务流程

### 主流程

1. 读取当前质量报告，确认 `02CSS相关/CSS重构` 为本轮治理对象
2. 补充 `package.json` 脚本入口
3. 执行批量标题修复
4. 对修复结果做二次检查，并统一改为带上下文的语义标题
5. 执行 `docs:sync`
6. 执行 `docs:check`
7. 回写开发记录、开发笔记和质量基线
8. 完成 Dao Commit 子任务提交准备

### 分支流程

如果批量修复后没有新增重复标题和指标回归，仍然执行目录内语义化收口，避免章节标题缺少模块上下文。

### 异常流程

如果出现以下任一情况：

- 标题重复数量增加
- 构建失败
- 校验指标回归

则必须在当前轮次内继续修复，直至 `docs:check` 重新通过。

## 模块边界

- 仅治理 `02CSS相关/CSS重构`
- 不触碰 `05Nodejs` 及其相关本地工作区
- 不修改 `scripts/fix-missing-h1.mjs` 本身
- 不把本轮扩展成 `02CSS相关` 全模块批量治理

## 自测设计

本轮自测顺序固定为：

1. `npm run docs:fix-h1:css-refactor`
2. `npm run docs:sync`
3. `npm run docs:check`

全部通过后，才算 `M23` 当前轮次完成。
