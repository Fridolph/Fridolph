# M5详细设计：面试性能优化子目录治理深化

这份文档用于说明 `M5` 的详细设计。

## 设计目标

在 `M2` 已完成热点模块扩面、`M4` 已验证同模块连续治理后，继续回到当前最高热点模块 `00面试相关整理`，对其高价值子目录 `01前端性能优化` 做一轮边界清晰的标题治理，进一步降低全仓库缺少一级标题规模。

## 为什么选择 `00面试相关整理/01前端性能优化`

- 当前质量报告显示 `00面试相关整理` 仍是第一热点模块，`missingTitleCount = 66`
- `01前端性能优化` 子目录当前还有 `7` 篇文档缺少一级标题，体量适中，适合一轮闭环治理
- 该目录大多是性能优化知识卡片和专题笔记，命名容易产生通用标题，需要在本轮验证“统一前缀命名”策略
- 它不与当前用户本地 Node 学习笔记改动区域重叠，适合安全推进

## 业务流程

### 主流程

1. 读取当前质量报告，确认 `01前端性能优化` 为本轮治理对象
2. 补充 `package.json` 脚本入口
3. 执行批量标题修复
4. 对修复结果做二次检查，并统一改为 `前端性能优化：<主题>` 命名
5. 执行 `docs:sync`
6. 执行 `docs:check`
7. 回写开发记录、开发笔记和质量基线
8. 完成 Dao Commit 提交

### 分支流程

如果批量修复后未出现重复标题和指标回归，则直接进入自测与回写阶段。

### 异常流程

如果出现以下任一情况：

- 标题重复数量增加
- 构建失败
- 校验指标回归

则必须在当前轮次内继续修复，直至 `docs:check` 重新通过。

## 模块边界

- 仅治理 `00面试相关整理/01前端性能优化`
- 不触碰 `05Nodejs/Node入门2` 及其相关本地改动
- 不修改 `scripts/fix-missing-h1.mjs` 本身
- 不把本轮扩展成跨模块批量治理

## 自测设计

本轮自测顺序固定为：

1. `npm run docs:fix-h1:interview-performance`
2. `npm run docs:sync`
3. `npm run docs:check`

全部通过后，才算 `M5` 当前轮次完成。
