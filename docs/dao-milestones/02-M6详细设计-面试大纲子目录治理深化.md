# M6详细设计：面试大纲子目录治理深化

这份文档用于说明 `M6` 的详细设计。

## 设计目标

在 `M5` 已验证热点模块内继续深挖可稳定降指标后，继续回到 `00面试相关整理`，对其当前最高价值子目录 `2019年前端面试大纲整理` 进行一轮标题治理，进一步降低热点模块的缺少一级标题数量。

## 为什么选择 `00面试相关整理/2019年前端面试大纲整理`

- 当前质量报告显示该子目录仍有 `16` 篇文档缺少一级标题，是 `00面试相关整理` 内贡献最高的治理对象
- 该目录包含多层子目录，能验证当前治理流程在“目录更深、主题更散”的情况下是否仍能稳定复用
- 已提前检测到 `00`、`hybrid` 等弱语义标题存在重复风险，因此适合在本轮验证“统一前缀命名”策略
- 它不与当前用户本地 Node 学习笔记改动区域重叠，适合持续安全推进

## 业务流程

### 主流程

1. 读取当前质量报告，确认 `2019年前端面试大纲整理` 为本轮治理对象
2. 补充 `package.json` 脚本入口
3. 执行批量标题修复
4. 对修复结果做二次检查，并统一改为 `面试大纲：<主题>` 命名
5. 执行 `docs:sync`
6. 执行 `docs:check`
7. 回写开发记录、开发笔记和质量基线
8. 完成 Dao Commit 提交

### 分支流程

如果批量修复后未出现重复标题和指标回归，仍执行统一前缀命名收口，以提升检索语义稳定性。

### 异常流程

如果出现以下任一情况：

- 标题重复数量增加
- 构建失败
- 校验指标回归

则必须在当前轮次内继续修复，直至 `docs:check` 重新通过。

## 模块边界

- 仅治理 `00面试相关整理/2019年前端面试大纲整理`
- 不触碰 `05Nodejs/Node入门2` 及其相关本地改动
- 不修改 `scripts/fix-missing-h1.mjs` 本身
- 不把本轮扩展成跨模块批量治理

## 自测设计

本轮自测顺序固定为：

1. `npm run docs:fix-h1:interview-outline`
2. `npm run docs:sync`
3. `npm run docs:check`

全部通过后，才算 `M6` 当前轮次完成。
