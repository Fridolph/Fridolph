# M7详细设计：面试知识归纳子目录治理深化

这份文档用于说明 `M7` 的详细设计。

## 设计目标

在 `M6` 已完成面试大纲型资料治理后，继续回到 `00面试相关整理`，对其下一批高价值子目录 `2017面试准备及相关知识点整理` 进行一轮标题治理，进一步降低热点模块的缺少一级标题数量。

## 为什么选择 `00面试相关整理/2017面试准备及相关知识点整理`

- 当前质量报告显示该子目录仍有 `13` 篇文档缺少一级标题，是 `00面试相关整理` 内下一批高价值治理对象
- 该目录以老版知识归纳与面试总结为主，命名中包含编号、`note`、`总结`、`技巧` 等弱语义标题，适合继续验证统一前缀命名策略
- 它与上一轮面试大纲目录相邻，但内容风格不同，能帮助我们验证当前方法对不同资料形态是否仍然稳定
- 它不与当前用户本地 Node 学习笔记改动区域重叠，适合持续安全推进

## 业务流程

### 主流程

1. 读取当前质量报告，确认 `2017面试准备及相关知识点整理` 为本轮治理对象
2. 补充 `package.json` 脚本入口
3. 执行批量标题修复
4. 对修复结果做二次检查，并统一改为 `面试知识归纳：<主题>` 命名
5. 执行 `docs:sync`
6. 执行 `docs:check`
7. 回写开发记录、开发笔记和质量基线
8. 完成 Dao Commit 提交

### 分支流程

如果批量修复后未出现重复标题和指标回归，仍执行统一前缀命名收口，以提升检索语义稳定性。

### 异常流程

如果出现以下任一情况：

- 标题重复数量增加
- 构建失败
- 校验指标回归

则必须在当前轮次内继续修复，直至 `docs:check` 重新通过。

## 模块边界

- 仅治理 `00面试相关整理/2017面试准备及相关知识点整理`
- 不触碰 `05Nodejs/Node入门2` 及其相关本地改动
- 不修改 `scripts/fix-missing-h1.mjs` 本身
- 不把本轮扩展成跨模块批量治理

## 自测设计

本轮自测顺序固定为：

1. `npm run docs:fix-h1:interview-2017`
2. `npm run docs:sync`
3. `npm run docs:check`

全部通过后，才算 `M7` 当前轮次完成。
