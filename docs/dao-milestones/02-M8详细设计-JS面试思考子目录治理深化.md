# M8详细设计：JS面试思考子目录治理深化

这份文档用于说明 `M8` 的详细设计。

## 设计目标

在 `M7` 已继续压降面试热点模块后，沿着既定顺序推进 `00面试相关整理/JS面试相关思考`，完成一轮标题治理，让这一组 JS 面试思考文章进入可稳定检索、可稳定引用的状态。

## 为什么选择 `00面试相关整理/JS面试相关思考`

- 当前质量报告显示该子目录仍有 `10` 篇文档缺少一级标题，规模适中，适合一轮完整闭环
- 该目录由连续编号文章和 `JavaScript相关` 子目录组成，能够验证“主线文章 + 补充文章”的混合结构治理方式
- 当前不存在重复标题命中，但编号与泛化文件名仍然偏弱语义，因此仍适合统一前缀命名
- 它不与当前用户本地 Node 学习笔记改动区域重叠，适合继续安全推进

## 业务流程

### 主流程

1. 读取当前质量报告，确认 `JS面试相关思考` 为本轮治理对象
2. 补充 `package.json` 脚本入口
3. 执行批量标题修复
4. 对修复结果做二次检查，并统一改为 `JS面试思考：<主题>` 命名
5. 执行 `docs:sync`
6. 执行 `docs:check`
7. 回写开发记录、开发笔记和质量基线
8. 完成 Dao Commit 提交

### 分支流程

如果批量修复后未出现重复标题和指标回归，仍执行统一前缀命名收口，以提升检索语义稳定性。

### 异常流程

如果出现以下任一情况：

- 标题重复数量增加
- 构建失败
- 校验指标回归

则必须在当前轮次内继续修复，直至 `docs:check` 重新通过。

## 模块边界

- 仅治理 `00面试相关整理/JS面试相关思考`
- 不触碰 `05Nodejs/Node入门2` 及其相关本地改动
- 不修改 `scripts/fix-missing-h1.mjs` 本身
- 不把本轮扩展成跨模块批量治理

## 自测设计

本轮自测顺序固定为：

1. `npm run docs:fix-h1:js-interview-thinking`
2. `npm run docs:sync`
3. `npm run docs:check`

全部通过后，才算 `M8` 当前轮次完成。
