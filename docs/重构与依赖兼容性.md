# 学习站点重构与依赖兼容性

检查日期：2026-11-09。版本来自 npm registry，实际安装结果以 `package.json` 与 `pnpm-lock.yaml` 为准。

## 项目定位与目录迁移

展示名称改为“Web 开发学习宝典”，覆盖前端、后端、AI 应用、通用基础与性能优化。仓库名与 Pages 子路径继续使用 `FE-prepare-interview`。

| 原目录 | 新目录 | 学习方式 |
| --- | --- | --- |
| 直击概念 | 概念与原理 | 理解概念与机制 |
| 编写代码 | 编码与实践 | 动手验证与实现 |
| 面试官问 | 学习自测 | 问题、参考回答与回顾 |

目录、导航、侧边栏、站内链接与贡献说明同步迁移，文章的技术目录编号和 s_/c_/q_ 文件前缀保留。历史面经通过学习资源入口保留。

开发服务为旧栏目 URL 返回跳转；生产构建为每篇迁移文章生成兼容 HTML 入口，保留查询参数与锚点。兼容入口不进入本地搜索索引，新地址用于编辑入口和 sitemap。

学习路线连接本站、[AI-Journey-land](https://github.com/Fridolph/AI-Journey-land)、[个人博客](https://fridolph.github.io/fridolph-blog/)与 [AI Journey Fighting](https://fridolph.github.io/AI-Journey-Fighting/)。各项目独立维护；规划中的 demo 明确标记，后续逐步补充代码位置、执行结果与复盘。

## 运行环境

- Node.js：24.x，`.nvmrc` 与 `engines` 约束同一主版本。
- pnpm：12.14.0，通过 `packageManager` 固定；必须使用 pnpm 管理依赖。
- CI 读取上述环境配置，冻结锁文件安装，校验通过后构建。
- `pnpm-workspace.yaml` 只允许 esbuild 的安装构建脚本；新增需要执行脚本的依赖应单独评估。

修正了原先 `cross-env NODE_ENV=... && vitepress` 的写法：现在环境变量直接传递给 VitePress 进程，生产构建与预览统一使用 `/FE-prepare-interview/` 子路径。

- Demo Preview：有主题集成，但未使用其示例容器。


`pnpm check` 包含 lint、站点组件类型检查、旧 URL 迁移测试；教学文章中的片段不作为完整项目统一编译。`pnpm build` 负责全站渲染、死链检查、sitemap 和兼容跳转页生成。

浏览器验证应覆盖：首页五个分类、顶部与侧栏导航、学习路线、学习自测展开、旧地址跳转、中文搜索、Mermaid、图片预览，以及桌面/移动端与深色外观。

## 依赖审计仍有的限制

兼容范围内的间接依赖已刷新锁文件，包括 DOMPurify、Vue 编译器与 PostCSS 等。完整 `pnpm audit --json` 仍返回 **11 条公告：1 high、8 moderate、2 low**（检查时快照，后续以实际输出为准），涉及：

| 依赖链 | 剩余原因 | 后续方向 |
| --- | --- | --- |
| VitePress → Vite 5.4.21 → esbuild 0.21.5 | 上游稳定版约束无法取得所需修复主版本；包含开发服务器相关公告 | 跟踪 VitePress 稳定版升级；本地开发保持默认 loopback 监听，不向公网开放开发服务 |
| Mermaid → KaTeX 0.16.47 | 上游限定 ^0.16，公告修复版本 >=0.18.2 | 等待 Mermaid 的兼容升级，暂不强制跨版本覆盖 |
| ESLint / typescript-eslint → minimatch 10.2.6 | 上游约束为 10，公告修复版本 >=11.0.1 | 等待上游工具链更新 |

参考公告：[Vite](https://github.com/advisories/GHSA-587h-7wmj-h5pm)、[esbuild](https://github.com/advisories/GHSA-67mh-4wv8-2f99)、[KaTeX](https://github.com/advisories/GHSA-238p-pmpm-9mq7)、[minimatch](https://github.com/advisories/GHSA-g3hv-75wg-m249)。公告数量不等于已确认可利用的问题数量，本次没有进行攻击路径验证，也没有把这些告警标记为已修复。

Pages 部署的是静态构建产物，并不运行 Vite 开发服务器；这也不能据此忽略浏览器运行库的公告。当前选择是保留兼容稳定组合、公开记录限制，避免用未经支持的大版本覆盖制造新的兼容性问题。
