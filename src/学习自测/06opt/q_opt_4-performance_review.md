# 前端性能诊断自测

## 1. 你会从哪里开始优化一个慢页面？

**参考回答：** 先说明慢的场景与指标，收集真实用户分布，再在可控环境复现。通过 Network、Performance、服务端追踪定位主因，选改动做对照，确认体验收益、错误率和成本，而不是一次加入全部优化技巧。

**追问：** LCP、INP、CLS 分别衡量什么？为什么 TTFB 不能完全等于服务端执行时间？见[性能测量](/概念与原理/06opt/s_opt_10-measurement)。

## 2. 资源越合并越好吗？

**参考回答：** 合并减少部分请求开销，却可能增加无用下载、解析和缓存失效。HTTP/2 / 3 已支持多路复用，应结合页面路径拆包与复用；压缩、CDN、按需加载和移除未用代码都应有数据依据。

**追问：** Brotli 很有效，为什么 JavaScript 主线程时间仍然高？压缩不减少解压后的解析执行工作量。

## 3. 图片怎样同时兼顾速度和稳定性？

**参考回答：** 先控制实际像素与质量，用合适格式与回退，通过 srcset / sizes 适配设备，显式宽高预留空间。关键首屏图避免懒加载，非关键屏外图延后加载，必要时用 IntersectionObserver。Base64 只适合经过权衡的场景，不是一律更快。

**追问：** 给全部图片 preload / fetchpriority=high 为什么可能拖慢主图？

## 4. 回流重绘怎样定位，而不是靠口诀？

**参考回答：** 用面板确认布局和绘制成本，重点查读写交错造成的同步布局、大 DOM 与长任务。批量读写、局部更新和虚拟列表各有适用条件。transform / opacity 有合成优化机会，但不是绝对无成本，opacity=0 仍可能可聚焦或可点击。

**追问：** 创建 DocumentFragment 一定比直接追加快吗？不要脱离浏览器批处理和真实负载下结论。

## 5. 缓存失效与上线更新如何协调？

**参考回答：** 带内容哈希的静态资源可长期缓存，HTML 入口需要及时验证，旧资源留一段时间保证旧页面可用。no-cache 不等于不存储，no-store 不等于清空旧缓存；CDN 与 Service Worker 要分别设计版本和失效策略。

**追问：** worker 更新后旧页面仍开着怎么办？Cache Storage 为什么不能简单当成 HTTP 缓存的同一层？

## 6. 预加载、懒加载和离线能力有什么代价？

**参考回答：** 预加载提前使用带宽，懒加载延迟非关键工作，离线缓存提高断网可用性，但都引入资源争抢、陈旧内容和状态维护。Service Worker 不会永久运行，也不应缓存所有已登录 API。

**验证任务：** 设计一次冷缓存、热缓存、弱网、离线、发布新版本的对照实验，记录观察结果，避免只报告一次分数。
