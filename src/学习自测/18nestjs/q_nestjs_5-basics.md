## 1. 能简单介绍一下 NestJS 吗？为什么选择它？

::: details 参考回答

NestJS 是基于 Node.js、主要用 TypeScript 开发的后端框架。

Express、Koa 更轻量、更灵活，但模块怎么拆、依赖怎么管理，通常要团队自己约定。项目规模大了，如果缺少统一规范，维护成本就会上来。

NestJS 提供了比较完整的工程约定：用 Module 划分业务模块，Controller 接收请求，Service 处理业务，再通过依赖注入把它们组织起来，方便解耦和测试。像权限控制、参数校验、日志这些通用逻辑，也有 Guard、Pipe、Interceptor 等机制来承接。数据库操作则可以结合 TypeORM 或 Prisma。

对我来说，前端的 TypeScript 经验可以复用，学习后端时能减少语言切换成本。而且我希望掌握更系统的后端开发方式，所以选择学习 NestJS。

:::

**回答节奏**：这道开场题控制在一分钟左右，三分钟作为上限。讲完框架特点可以稍停一下，给面试官接话的机会；没有追问，再补充自己的学习动机。

## 2. NestJS 中的 IoC、DI、AOP 分别是什么？

::: details 参考回答

**IoC 是控制反转，DI 是依赖注入，AOP 是面向切面编程。**

IoC 是一种思想。拿依赖管理来说，以前是业务类自己 `new` 依赖，现在交给 NestJS 容器创建和管理，这就是控制权的反转。

DI 是实现 IoC 的一种常见方式。比如 Controller 需要 Service，我们注册好 Provider，再通过构造函数注入，就不用自己创建了，也方便替换实现和做单元测试。

AOP 主要是把日志、耗时统计这些通用逻辑从业务里抽出来。比如用 Interceptor 在请求处理前后统一加逻辑，就不用每个接口都重复写。

**简单说，IoC 是把依赖管理交给容器，DI 是容器把依赖提供给你，AOP 是把通用逻辑和业务逻辑分开。**

:::
