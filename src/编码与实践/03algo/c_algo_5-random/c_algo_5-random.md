# 随机整数、随机数组与均匀洗牌

旧笔记中的随机整数使用 `Math.round`，会使端点概率不同，部分公式还可能生成上界之外的数。这里统一使用整数闭区间 `[min, max]`，要求随机源返回 `[0, 1)`；默认 Math.random 不用于密码、令牌等安全场景。

<<< ./implementation.js

```js
randomInt(2, 4, () => 0) // 2
randomInt(2, 4, () => 0.999) // 4
shuffle([1, 2, 3]) // 原数组保持不变，结果为浅拷贝
```

Fisher–Yates 从末尾依次为位置 i 在 `[0, i]` 中均匀选一个元素，固定该位置后继续。若随机源均匀且抽样独立，n! 种排列各有 1/n! 的概率；时间 O(n)，这里为了保留输入，额外空间 O(n)。实际 Math.random 有有限精度，不能宣称绝对数学均匀或密码学安全。

`sort(() => Math.random() - 0.5)` 的比较器不满足排序契约，结果依赖排序实现且不均匀，不作为洗牌方案。

数组长度即使是合法整数，也不代表内存能承受。接收用户输入时另加业务长度上限。对象元素仍共享引用，shuffle 不会深拷贝对象。

**验证：** 三元素洗牌的选择路径只有 3 × 2 种，可以枚举所有路径验证排列覆盖；这比一次随机跑几万次就宣布“绝对均匀”更有解释力。
